- Provider 异常通过 `ProviderError.category` 与 `retryable` 属性进行统一分类，具体子类仅用于语义区分（连接失败、输出限制、图片错误）。
- 每个 provider 实现独立的 `_content` 转换器，将内部 blocks 表示映射到各自 API 的消息体格式，未知类型统一抛出 `ProviderError("Unsupported content type: ...")`。
- SSE 流式响应在 `complete` 中逐事件解码，通过 `on_event` 回调向外暴露 `text_delta`/`thinking_delta`/`tool_call_delta` 等事件，并在遇到 `error` 事件时调用 `stream_error` 转为结构化异常。
- 诊断信息通过 `RequestDiagnostics`/`DiagnosticStream` 在请求生命周期内累积，最终附着于异常的 `diagnostics` 字段，敏感字段（如 body）经 `Redactor` 脱敏后再向上传播。
- 工具调用校验遵循先 `validate_calls` 再 `validate_tool_pairs` 的两阶段检查，未执行的工具结果以拒绝文本块形式回写至 provider 消息。
