模块以 `base.py` 中的 `Provider` Protocol 和 `HTTPProvider` 抽象基类为中心：所有具体提供者继承 `HTTPProvider` 并实现 `complete`/`count_tokens`/`compact_messages` 等接口，由 `__init__.py` 的 `create_provider` 工厂按字符串键选择。

- 传输与诊断：`post_json`、`post_stream` 基于标准库 `urllib.request` 发起请求，统一包装 `RequestDiagnostics`/`DiagnosticStream` 记录 headers/body/elapsed；SSE 解析在 `_read_stream` 中完成，将 `[DONE]` 作为 None 终止事件。
- 错误体系：`ProviderError` 及其子类 `ProviderConnectionError`/`ProviderOutputLimitError`/`ProviderImageError` 通过 `_HTTP_CATEGORIES`、`_ERROR_CATEGORIES`、`_FINISH_CATEGORIES` 三级映射把 HTTP 状态码、provider error code/type、finish reason 归一为 `category`，并计算 `retryable` 与 `retry_after_seconds`。
- 具体实现：`anthropic.AnthropicProvider` 使用 Messages API + SSE；`openai.OpenAIProvider` 组合 `ResponsesMixin`（`responses.py`）以支持 Responses API 或 Chat Completions，并通过 `usage.py` 从下游 usage 快照推断 token 数。
- 重试：`retry.py` 的 `retry_call` 仅对 `exc.retryable == True` 的错误退避，支持 `SKILLS_AGENT_PROVIDER_MAX_ATTEMPTS` 与 `SKILLS_AGENT_PROVIDER_RETRY_BUDGET_SECONDS` 环境变量控制上限。
- 依赖方向：providers → base/diagnostics/retry/usage/responses，不被上层反向引用；工具回调、图片投影等通用能力集中在 `base.py` 的工具函数（`blocks`、`encoded_file`、`request_messages`、`validate_tool_pairs`、`tool_feedback_messages`）。
